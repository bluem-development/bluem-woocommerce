# Release 1.6.6 candidate

## Draft GitHub release notes

Improves diagnosis and stability of mandate shortcode transactions:

- Preserve SDK errors that were previously reported as “General error”, including
  errors returned by Bluem PHP's current response namespace and subclasses.
- Include redacted API errors, processing stage, response class/size/element names,
  HTTP status when available, and mandate ID in support emails. Raw XML, request
  bodies, entrance codes and bank details are excluded.
- Render numeric support-report fields, including stack-trace line numbers.
- Guard malformed input, unusable transaction URLs/IDs, missing status fields,
  configuration exceptions and failed request persistence before bank redirects.
- Fix logged-in debtor-reference lookup, missing counter fallback, non-object
  callback payloads and duplicate transaction-notification handling.
- Persist the returned mandate ID for callback correlation.

Also includes the changes merged since 1.6.5:

- #90: patched development dependency vulnerabilities, reproducible dependency
  audits and production dependency isolation checks.
- #91: reduce memory used by dependency-version reporting using cached local
  Composer installed metadata instead of decoding the whole lockfile.
- #92: update Playwright browser-test tooling to 1.63.0.
- #93: update the dependency-audit workflow's setup-node action to v7.

Runtime Bluem PHP remains 2.7.3. The Playwright and coding-standard updates are
for development and CI; they are excluded from the WordPress production package.
